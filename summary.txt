BTECH PROJECT DETAILED SUMMARY (END-TO-END)
===========================================

This document explains the full project flow in sequence: dataset curation, preprocessing, feature engineering, windowing/alignment, training, cross-validation, evaluation, live inference, and Streamlit UI.
All key steps are referenced to concrete code locations.

------------------------------------------------------------------------------
1) Problem framing and architecture
------------------------------------------------------------------------------
- Goal: predict stock behavior using both market prices and news sentiment.
- Primary model: hybrid late-fusion model with:
  - price LSTM branch
  - sentiment LSTM branch
  - company embedding
  - shared ANN layers
  - 3 outputs: return, volatility, direction
- Core implementation:
  - Hybrid model: `src/hybrid_model/late_fusion_model.py:L7-L91`
  - Hybrid estimator wrapper: `src/hybrid_model/sklearn_estimator.py:L24-L335`

------------------------------------------------------------------------------
2) Dataset curation from large news corpus (Kaggle pipeline scripts)
------------------------------------------------------------------------------
2.1 Frequency-based shortlist
- Script: `datasets/scripts/intial_shortlist.py`
- Reads big CSV in chunks and counts `Stock_symbol`.
- Keeps companies with >5000 rows.
- Code:
  - chunk processing: `datasets/scripts/intial_shortlist.py:L15-L26`
  - threshold filter: `datasets/scripts/intial_shortlist.py:L30-L35`

2.2 Real-company filtering
- Script: `datasets/scripts/second_shortlist.py`
- Uses curated `REAL_COMPANIES` list, filters chunk-wise, parses dates, removes invalid dates.
- Saves `real_companies_news.csv`.
- Code:
  - company list: `datasets/scripts/second_shortlist.py:L12-L20`
  - filter loop: `datasets/scripts/second_shortlist.py:L27-L43`
  - output save: `datasets/scripts/second_shortlist.py:L52-L54`

2.3 Best 1-year window per company + top-20 selection
- Script: `datasets/scripts/final_shortlist.py`
- For each company, uses sliding 365-day window and picks the highest-news window.
- Sorts by news count and keeps top 20.
- Saves `top20_companies_best_1yr_window.csv`.
- Code:
  - sliding logic: `datasets/scripts/final_shortlist.py:L25-L35`
  - top 20 save: `datasets/scripts/final_shortlist.py:L46-L50`

Why this is important:
- News coverage is inconsistent across companies and years.
- Window selection creates a more balanced and comparable training base.

5) Hybrid training and evaluation
------------------------------------------------------------------------------
5.1 Hybrid training script
- Script: `scripts/train_hybrid_late_fusion.py`
- Uses `GridSearchCV` over hyperparameter grid and custom scoring.
- Selection metric: negative RMSE on return head (`_neg_return_rmse`).
- Saves best model `.pt` and best params JSON.
- Saved files:
  - `data/processed/model_artifacts/hybrid_late_fusion_best.pt`
  - `data/processed/model_artifacts/hybrid_late_fusion_best_params.json`.
- Code:
  - custom scoring: `scripts/train_hybrid_late_fusion.py:L29-L35`
  - grid setup/fit: `scripts/train_hybrid_late_fusion.py:L95-L105`
  - artifact saves: `scripts/train_hybrid_late_fusion.py:L107-L152`

5.2 Hybrid evaluation script
- Script: `scripts/evaluate_hybrid_r2.py`
- Rebuilds estimator from best params and runs fold-wise evaluation.
- Metrics:
  - return R2/RMSE
  - direction accuracy
  - volatility RMSE/MAE
  - high-confidence directional accuracy based on `abs(pred_return)`
- Code:
  - fold loop: `scripts/evaluate_hybrid_r2.py:L90-L120`
  - confidence thresholds: `scripts/evaluate_hybrid_r2.py:L110-L130`
  - JSON result save: `scripts/evaluate_hybrid_r2.py:L132-L160`
- Saved metrics file: `data/processed/model_artifacts/hybrid_r2_scores.json`.

6) Cross-validation methodology (critical note for report)
------------------------------------------------------------------------------
Important conceptual point:
- For financial time series, TimeSeries CV is methodologically preferred over shuffled KFold to preserve temporal ordering and reduce leakage risk.

Current repository state:
- Hybrid scripts currently run KFold (time-series code commented):
  - train: `scripts/train_hybrid_late_fusion.py:L84-L90`
  - eval: `scripts/evaluate_hybrid_r2.py:L72-L78`
- Price-only/news-only scripts currently run TimeSeriesSplit:
  - price-only train/eval: `scripts/price_only_ablation/train_price_only_late_fusion.py:L82-L85`,
    `scripts/price_only_ablation/evaluate_price_only_r2.py:L70-L73`
  - news-only train/eval: `scripts/news_only_ablation/train_news_only_late_fusion.py:L82-L85`,
    `scripts/news_only_ablation/evaluate_news_only_r2.py:L70-L73`
- Config files declare `cv_strategy: "timeseries"`:

8) Live inference pipeline (new independent flow)
------------------------------------------------------------------------------
Main file: `src/live_pipeline.py`

8.1 Live price fetch
- Uses Yahoo Finance via existing `collect_price_data`.
- Pulls last ~30 calendar days, keeps `window_size+1` trading rows per ticker.
- Saves `data/processed/live_prices.csv`.
- Code:
  - fetch + trim: `src/live_pipeline.py:L205-L223`

8.2 Live news fetch (Finnhub)
- Per ticker, queries Finnhub company news from first to last fetched trading day.
- Converts API payload into pipeline schema: `ticker, published_date, news_text`.
- Code:
  - Finnhub call: `src/live_pipeline.py:L47-L67`
  - schema conversion: `src/live_pipeline.py:L70-L95`
  - per-ticker fetch loop: `src/live_pipeline.py:L225-L245`

8.3 Reuse existing preprocessing exactly
- Calls existing functions directly (no rewritten logic):
  - `build_daily_news_price_alignment(...)`
  - `build_daily_sentiment(...)`
  - `align_modalities(...)`
  - `build_flattened_hybrid_input(...)`
- Code:
  - processors invoked: `src/live_pipeline.py:L247-L289`

8.4 Latest-window selection and inference
- Keeps most recent aligned row per ticker.
- Rebuilds hybrid estimator architecture from best params.
- Loads trained state dict (`hybrid_late_fusion_best.pt`), applies same estimator scaling setup from training NPZ.
- Predicts return/direction/volatility and writes JSON.
- Code:
  - latest window rows: `src/live_pipeline.py:L280-L282`
  - model reconstruction + load: `src/live_pipeline.py:L112-L169`
  - prediction mapping/output save: `src/live_pipeline.py:L298-L320`

Output files:
- `data/processed/live_prices.csv`
- `data/processed/live_predictions.json`
- (also article sentiment dump) `data/processed/live_sentiment_article_level.csv`

11) Complete flow summary in one line
------------------------------------------------------------------------------
Large raw news dataset -> curated companies -> per-company best 1-year windows -> chunked news+price ingestion -> FinBERT article sentiment -> top-k weighted daily sentiment -> temporal alignment/window engineering with decay/gating/scaling -> flattened model input -> hybrid/ablation training with CV -> fold-wise evaluation -> independent live pipeline with yfinance+finnhub -> Streamlit dashboard with 24-hour auto-refresh + manual override.
